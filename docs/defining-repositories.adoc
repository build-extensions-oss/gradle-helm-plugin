= Defining Repositories

Chart repositories are external storages of Helm charts.

You can use the `helm.repositories` block to define repositories:

[source,groovy,role="primary"]
.Groovy
----
helm {
    repositories {
        example {
            url 'http://helm-repo.example.com/'
        }
    }
}
----

[source,kotlin,role="secondary"]
.Kotlin
----
helm {
    repositories {
        create("example") {
            url("http://helm-repo.example.com/")
        }
    }
}
----

Defining a repository will automatically add a task `helmAdd<X>Repository` (for example,
`helmAddExampleRepository`) that does the equivalent of `helm repo add`.


For convenience, some shorthand methods are defined for registration of some well-known repositories:

[source,groovy,role="primary"]
.Groovy
----
helm {
    repositories {
        // registers the Helm stable repo under the name "stable"
        helmStable()
        // registers the Helm incubator repo under the name "incubator"
        helmIncubator()
        // registers the Bitnami repo under the name "bitnami"
        bitnami()
    }
}
----

[source,kotlin,role="secondary"]
.Kotlin
----
helm {
    repositories {
        // registers the Helm stable repo under the name "stable"
        helmStable()
        // registers the Helm incubator repo under the name "incubator"
        helmIncubator()
        // registers the Bitnami repo under the name "bitnami"
        bitnami()
    }
}
----


== Configuring Repository Credentials

If a chart repository requires authentication, you can configure credentials using the `credentials`
block. It works very similarly to other places in Gradle where credentials are used.

[source,groovy,role="primary"]
.Groovy
----
helm {
    repositories {
        example {
            url 'http://helm-repo.example.com/'
            credentials {
                username = 'user'
                password = 'password'
            }
        }
    }
}
----

[source,kotlin,role="secondary"]
.Kotlin
----
helm {
    repositories {
        create("example") {
            url("http://helm-repo.example.com/")
            credentials {
                username.set("user")
                password.set("password")
            }
        }
    }
}
----

In addition to username/password credentials, certificate credentials based on PEM files
are also supported:

[source,groovy,role="primary"]
.Groovy
----
import io.github.build.extensions.oss.gradle.plugins.helm.dsl.credentials.CertificateCredentials

helm {
    repositories {
        example {
            url 'http://helm-repo.example.com/'

            credentials(CertificateCredentials) {
                certificateFile = file 'path/to/cert.pem'
                keyFile = file 'path/to/key.pem'
            }
        }
    }
}
----

[source,kotlin,role="secondary"]
.Kotlin
----
import io.github.build.extensions.oss.gradle.plugins.helm.dsl.credentials.CertificateCredentials

helm {
    repositories {
        create("example") {
            url("http://helm-repo.example.com/")

            credentials(CertificateCredentials::class.java) {
                certificateFile.set(file("path/to/cert.pem"))
                keyFile.set(file("path/to/key.pem"))
            }
        }
    }
}
----


== OCI Registries

Helm can pull charts from OCI registries (dependency URLs starting with `oci://`). Such a registry has no
index and cannot be registered with `helm repo add`, but it usually requires a `helm registry login` before
charts can be pulled from it.

Declare the registry in the `helm.registries` block, with its host and credentials:

[source,groovy,role="primary"]
.Groovy
----
helm {
    registries {
        artifactory {
            host = 'registry.example.com'
            credentials {
                username = providers.environmentVariable('REGISTRY_USER')
                password = providers.environmentVariable('REGISTRY_PASSWORD')
            }
        }
    }
}
----

[source,kotlin,role="secondary"]
.Kotlin
----
helm {
    registries {
        create("artifactory") {
            host.set("registry.example.com")
            credentials {
                username.set(providers.environmentVariable("REGISTRY_USER"))
                password.set(providers.environmentVariable("REGISTRY_PASSWORD"))
            }
        }
    }
}
----

The `host` is what `helm registry login` expects: the host name, optionally with a port
(`registry.example.com:5000`), without a scheme or path. Certificate credentials and a `caFile` are supported as
for repositories.

There is no task to run: the tasks that update or build chart dependencies log in by themselves, right before
they call Helm. They only log in

* when they actually run - an up-to-date or skipped task does not contact the registry, and
* to registries that a dependency of their chart is pulled from, i.e. whose `host` matches the
  `repository: oci://<host>/...` URL of a dependency in `Chart.yaml`.

The password is passed to Helm on the standard input (`--password-stdin`), never on the command line.

A repository in the `helm.repositories` block whose URL uses the `oci` scheme is treated the same way: the
dependency tasks log in to it with its credentials, and it is left out of `helm repo add` and `helm repo update`.
Running its `helmAdd<X>Repository` task explicitly logs in to the registry.

NOTE: The plugin points Helm at its own configuration directory (see `helm.xdgConfigHome`), so a
`helm registry login` done in a shell outside of Gradle is not visible to the Helm tasks of the build.

=== Logging in for other tasks

For anything other than chart dependencies, register a `HelmRegistryLogin` task and wire it with `dependsOn`
yourself. It logs in every time it runs, and it is not connected to any other task automatically:

[source,groovy,role="primary"]
.Groovy
----
import io.github.build.extensions.oss.gradle.plugins.helm.command.tasks.HelmRegistryLogin

def helmRegistryLogin = tasks.register('helmRegistryLogin', HelmRegistryLogin) {
    registry = 'registry.example.com'
    username = providers.environmentVariable('REGISTRY_USER')
    password = providers.environmentVariable('REGISTRY_PASSWORD')
}
----

[source,kotlin,role="secondary"]
.Kotlin
----
import io.github.build.extensions.oss.gradle.plugins.helm.command.tasks.HelmRegistryLogin

val helmRegistryLogin by tasks.registering(HelmRegistryLogin::class) {
    registry.set("registry.example.com")
    username.set(providers.environmentVariable("REGISTRY_USER"))
    password.set(providers.environmentVariable("REGISTRY_PASSWORD"))
}
----

All of this is compatible with the configuration cache. Avoid calling `helm.execHelm("registry", "login")` from a
`doFirst` block instead: the build script lambda references the `Project`, so Gradle cannot store the task in the
configuration cache.
